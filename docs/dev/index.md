# 开发

## 概述

Seatide服务器基于阿里云ECS抢占式实例，遵从一种弹性、按需的运行模式。这意味着服务器并非如大部分Minecraft服务器那样长久地开启、运行在一个固定的实例上，而是运行在不固定的*计算资源*上，这使得我们可以及时根据玩家的游戏需求对实例规格进行调整，以及在无玩家游戏需求的游戏低谷期及时释放计算资源以节省成本。

为了实现上面的这套模式，我们实现了[go-aliyunmc](https://github.com/Subilan/go-aliyunmc)。该程序是Seatide运行的软件基础设施，主要用于管理和监控实例资源和服务器，并为玩家自助开启服务器提供支持。同时该程序还实现了除实例管理外的其它需求，用于为一个游戏社区提供配套平台，如玩家账号的统一管理、论坛接口以及将来的Java插件集成。

:::note
该项目原以一种通用的方式设计以期能够被他人通过配置快速地复用，但目前我们已将其作为定制的特化软件开发，不再考虑外部需求。
:::

除了上面提到的软件基础设施外，Seatide也在积极地借助Coding Agent的能力创建基于Paper API的游戏插件，以期将想象中的游戏玩法拓展变为现实，创造独特的Seatide游戏体验。

## 参与开发

我们主要使用Coding Agent进行开发，不需要手写代码。但要参与开发，最好满足下列条件：
- 了解GitHub和Git的使用方法，尤其是Git中分支、Merge/Rebase概念
- 了解任意一种代码生成Harness的使用方法，Harness、Model的区别
- 了解判定一个需求的可行性的基本方法，避免“抽卡”、“许愿式编程”
- 了解Minecraft插件与模组的区别（仅游戏插件开发）

我们的仓库主要放在seatidemc组织下面：https://github.com/seatidemc，部分仓库是私有的。
